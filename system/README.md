# System

## Purpose

The machine-readable control plane of the library's AI-native
architecture. Agents, orchestrators and CI read these files; people read
the explanations in [`docs/architecture/`](../docs/architecture/).

## Structure

```text
system/
├── registry/      Source of truth: agents, skills, routing, models,
│                  permissions, review gates, memory, graph ontology,
│                  workflows, budgets
├── schemas/
│   ├── registry/  JSON Schemas for the registry files
│   └── metadata/  JSON Schemas for library records (books, authors, ...)
├── generated/     Catalogs rendered from the registries (do not edit)
├── memory/        Project memory, one file per project (created on use)
└── reports/       Monthly cost and evaluation reports (created on use)
```

## Rules

- Change a registry, then run `python scripts/validate-registry.py` and
  `python scripts/generate-registry-docs.py`, and commit both.
- Registries use model classes (`haiku`, `sonnet`, `opus`). Concrete model
  IDs and prices appear only in `registry/models.yaml`.
- Every file here is owned by Tier 5 and the repository owner
  (`.github/CODEOWNERS`), except `generated/` (regenerated by script) and
  `memory/projects/` (project memory).
