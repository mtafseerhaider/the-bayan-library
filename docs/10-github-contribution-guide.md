# GitHub Contribution Guide

## Purpose

The GitHub Contribution Guide defines how contributors propose, discuss, review,
and integrate changes into The Bayan Library.

The objective is to maintain a high-quality, well-organized, and sustainable
repository while encouraging meaningful participation.

Contributions should improve the repository's usefulness, accuracy,
organization, or discoverability.

## Governance Model

The Bayan Library follows a hybrid governance model.

The repository is:

- Personal first.
- Public second.
- Community supported.
- Editor governed.

Final editorial authority remains with the repository owner.

External contributions are welcomed and encouraged.

## Contribution Principles

All contributions should support at least one of the following goals:

- Knowledge preservation.
- Intellectual discovery.
- Educational value.
- Improved organization.
- Better documentation.
- Enhanced searchability.
- Improved cross-linking.

Contributions should prioritize quality over quantity.

## Contributor Expectations

Contributors are expected to:

- Be respectful.
- Be constructive.
- Be accurate.
- Be transparent.
- Follow repository standards.
- Document significant changes.

Collaboration should strengthen the library rather than create unnecessary
complexity.

## Ways to Contribute

Contributors may:

- Add book summaries.
- Add author profiles.
- Improve documentation.
- Create reading paths.
- Add historical context.
- Improve metadata.
- Expand canon coverage.
- Report errors.
- Improve automation scripts.
- Improve knowledge graph connections.

Contributions are not limited to these categories.

## Before Contributing

Before creating a contribution:

1. Review repository structure.
2. Read relevant documentation.
3. Check for existing content.
4. Search for duplicate submissions.
5. Follow established templates.

Consistency is preferred over individual formatting preferences.

## Content Quality Standards

Contributed content should be:

- Accurate.
- Well structured.
- Clearly written.
- Relevant.
- Properly linked.

Contributions should add value rather than volume.

## Content That Should Not Be Added

The repository should avoid:

- Duplicate content.
- Low-quality summaries.
- Unsourced factual claims.
- Plagiarized content.
- Copyright violations.
- Promotional material.
- Spam.

The goal is long-term intellectual value.

## Branching Requirement

Contributors should never commit directly to the main branch.

All work should be performed in dedicated branches.

Examples:

```text
feature/add-book-war-and-peace

feature/add-author-ibn-sina

feature/add-world-poetry-path

docs/update-readme

research/islamic-philosophy-canon

refactor/metadata-structure
```

## Branch Naming Rules

Branch names should:

- Use lowercase letters.
- Use hyphens.
- Be descriptive.
- Reflect the work being performed.

Preferred formats:

```text
feature/<name>

docs/<name>

research/<name>

refactor/<name>

automation/<name>

fix/<name>
```

## Commit Standards

The repository follows Conventional Commits.

Examples:

```text
feat(book): add war and peace summary

feat(author): add ibn sina profile

feat(poetry): add hafez biography

feat(canon): update top 100 books

docs(readme): improve repository navigation

refactor(metadata): normalize author schema

fix(links): correct broken references
```

## Commit Message Rules

Commit messages should:

- Be concise.
- Describe the change.
- Follow Conventional Commits.
- Explain intent clearly.

Poor example:

```text
updated stuff
```

Preferred example:

```text
feat(book): add executive summary for muqaddimah
```

## Pull Request Requirement

All meaningful changes should be submitted through pull requests.

Pull requests create transparency and review opportunities.

Even repository maintainers should prefer pull requests for significant changes.

## Pull Request Template

Every pull request should contain:

```markdown
## Summary

## Reason

## Files Added

## Files Modified

## Knowledge Impact

## Future Opportunities
```

The template helps maintain consistency.

## Pull Request Review Criteria

Reviewers should evaluate:

- Accuracy.
- Clarity.
- Completeness.
- Repository fit.
- Metadata quality.
- Knowledge graph impact.

Approval should reflect repository goals rather than personal preference.

## Review Outcomes

Pull requests may be:

- Accepted.
- Accepted with modifications.
- Deferred.
- Rejected.

Review decisions should include clear reasoning whenever practical.

## Documentation Contributions

Documentation contributions are highly encouraged.

Examples:

- Repository guides.
- Methodology improvements.
- Reading-path documentation.
- Canon explanations.
- Metadata documentation.

Documentation is considered first-class repository content.

## Metadata Contributions

Metadata updates should:

- Follow schema definitions.
- Pass validation.
- Avoid duplicate identifiers.
- Preserve existing references.

Metadata changes should be carefully reviewed because they affect automation.

## Knowledge Graph Contributions

Graph-related contributions may include:

- New relationships.
- Improved influence chains.
- Additional references.
- Corrected connections.

Relationships should be supported by reputable sources whenever possible.

## Canon Contributions

Canon-related contributions require special care.

Examples:

- Top 100 Books revisions.
- Islamic Canon updates.
- Poetry Canon updates.
- Reading list changes.

Contributors should provide reasoning for significant ranking decisions.

## Book Contributions

New book entries should include:

- Metadata.
- Summary.
- Themes.
- Related works.
- Author links.

Books should integrate into the broader repository rather than exist in
isolation.

## Author Contributions

New author pages should include:

- Biography.
- Historical context.
- Major works.
- Influence network.
- Related thinkers.

Author pages should support knowledge graph development.

## Poetry Contributions

Poetry contributions should include:

- Poet metadata.
- Literary context.
- Major works.
- Influence relationships.
- Theme associations.

Poetry should remain integrated with the wider repository.

## Islamic Civilization Contributions

The repository places special emphasis on Islamic intellectual history.

Contributors are encouraged to improve coverage of:

- Philosophy.
- Theology.
- Mysticism.
- History.
- Literature.
- Science.

Contributions should remain historically accurate and non-sectarian.

## Source Expectations

Preferred sources include:

- Academic publications.
- University presses.
- Scholarly journals.
- Critical editions.
- Primary texts.
- Established reference works.

Unsourced claims should be avoided.

## Copyright Compliance

Contributors must respect copyright law.

Do not submit:

- Unauthorized full books.
- Copyrighted material without permission.
- Excessive excerpts.

Summaries, commentary, metadata, and original analysis are preferred.

## Issue Reporting

Issues should be used for:

- Errors.
- Missing content.
- Broken links.
- Metadata problems.
- Structural suggestions.
- Feature requests.

Issues should include enough information to reproduce or understand the problem.

## Automation Contributions

Contributors may improve:

- Validation scripts.
- Index generation.
- Knowledge graph tooling.
- Reading-path generation.
- Metadata automation.

Automation should improve maintainability and reduce manual effort.

## Communication Standards

Repository discussions should remain:

- Professional.
- Respectful.
- Evidence based.
- Constructive.

Personal attacks and unnecessary hostility are not acceptable.

## Acknowledgment of Contributors

Contributions should be recognized whenever practical.

Recognition helps encourage long-term participation and repository growth.

## Contribution Workflow

The recommended workflow is:

1. Identify a need.
2. Create an issue if appropriate.
3. Create a branch.
4. Make changes.
5. Validate content.
6. Submit a pull request.
7. Address review feedback.
8. Merge after approval.

Following a common workflow improves consistency.

## Success Criteria

The contribution process succeeds when it:

- Encourages participation.
- Preserves quality.
- Improves organization.
- Maintains consistency.
- Supports long-term growth.

The goal is a repository that becomes increasingly valuable over time.

## Guide Summary

The GitHub Contribution Guide establishes the standards by which The Bayan
Library grows and evolves.

Every contribution should strengthen the repository's mission of preserving,
organizing, and connecting humanity's most important intellectual achievements.
